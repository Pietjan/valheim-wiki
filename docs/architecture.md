# Architecture

A static Valheim wiki (GitHub Pages) generated by Go, with a Go→WASM seed
viewer. Everything the game knows is read once from the client's asset
bundles into `data/*.json` and `assets/icons/**` (committed); CI then
builds the site with Go alone.

```
cmd/wiki-data     bundles → data/*.json + assets/icons/{items,pieces,effects,skills,map,ui}/   (needs the game client)
cmd/wiki-icons    valheim-npc/meshes → assets/icons/{locations,creatures}/*.png  (software rasterizer; needs the meshes)
cmd/wiki          data/ + web/ → public/   (the static site generator)
cmd/world-wasm    worldgen → web/static/world/world.wasm   (the seed engine)
internal/model    the data model shared by all of the above (JSON shapes)
internal/worldgen, worldmap, stablehash, unityrandom, scalar   copied from valheim-world: the seed → world port
internal/vmsh     the mesh format copied from valheim-world
internal/unity/*, internal/assets   Unity bundle readers copied from valheim-npc / valheim-forge
internal/render   software rasterizer used by wiki-icons
internal/site     the generator: pages, templates, search index, your-world hooks
web/templates     html/template files
web/static        css, js, fonts, ui sprites, map textures, world wasm
data/             extracted JSON (committed)
assets/icons/     extracted + rendered PNGs (committed)
public/           build output (gitignored)
```

## Game data: the contract

`internal/model` is the contract. `model.DB` is written as one file per
field by `DB.Write(dir)` and read back by `model.Read(dir)`. References
between things are prefab names (`SwordBronze`, `Troll`, `Crypt2`), never
display names. Display names are English, resolved at extraction time
with `X.Text` (localization) or `X.NameOf(prefab, token)` (the hand-kept
`names.tsv` first, then the token).

Biomes are the slugs in `model.Biomes`; `model.BiomesOf(mask)` expands a
`Heightmap.Biome` bitmask. Per-level stats are base + step. Damage is a
map by type with only non-zero entries. Resistances are `[]DamageMod`
with only the non-Normal entries.

Each domain is one extractor file in `cmd/wiki-data` registered in
`main.go`'s `extractors` list. Extractors run in order and may read what
earlier ones put in `x.DB`. `env.go` provides: `X.Roots` (prefab name →
root GameObject), `X.Components(g)`, `X.Find(g, fields...)`,
`X.Children(g)`, `X.Walk(g, fn)`, `X.EachMono(fields, fn)` (every
MonoBehaviour with those top-level fields across all loaded files),
`X.GameObjectName(cab, pptr)` (prefab name behind a PPtr to a GameObject
*or* to one of its components), `X.Owner`, `X.RootName`, `X.DropTable`,
`X.Requirements`, `Damage`, `DamageMods`, `DamageModList`, `Biomes`,
`BiomeArea`, and `X.WantSprite(kind, name, ref)` for the icon pass. Field
readers `F/I/B/S/L/M` return zero values for missing fields.

Components are recognised by field names, not by script (MonoScripts are
not loaded): ItemDrop has `m_itemData`; Recipe has `m_resources`+`m_item`+
`m_minStationLevel`; CraftingStation `m_upgrader`+`m_craftRequireRoof`;
Piece `m_resources`+`m_icon`+`m_category`; Character `m_health`+
`m_faction` (WearNTear also has `m_health`: check `m_faction`);
CharacterDrop `m_drops`; Location `m_exteriorRadius`+`m_clearArea`; etc.
`wiki-data -probe Name1,Name2 -probe-out probe.txt` dumps every component
on a prefab (with its hierarchy) or an asset by `m_Name`: use it to see
real field names and values before coding.

Run: `make data` (or `go run ./cmd/wiki-data -softref "$(SOFTREF)" -out data -icons assets/icons`).
Loading takes 10 s and peaks at ~6 GB; run one at a time and prefer
`-only items,recipes -no-icons -out <scratch>` while developing.

## Icons

- `assets/icons/items/<prefab>.png` (+ `<prefab>_<n>.png` for variants),
  `pieces/`, `effects/`, `skills/`, `stations/`: the game's sprites, as
  the inventory draws them (64×64 typically, transparent).
- `assets/icons/map/mapicon_*.png`: the game's map pins and location
  icons (start, trader, hildir, bogwitch camp, upgradestation, boss, ...).
- `assets/icons/locations/<prefab>.png`, `creatures/<prefab>.png`: round
  256×256 PNGs rendered from the game's models by `wiki-icons`:
  transparent outside the circle, a dark warm disc behind the model,
  orthographic three-quarter view, lit like the game's clear day.
- `assets/icons/ui/`: the game's UI sprites (braids, panels) with
  `sprites.json` 9-slice borders; `web/static/fonts/`: Norse + Averia
  Serif Libre.

## The site

Base path aware (`/valheim-wiki/` on GitHub Pages): every URL in a
template goes through the `url` helper. Pages are directories with
`index.html`. Sections and URLs:

```
/                        home: seed field, sections, what's new
/items/                  index with filters; /items/<slug>/ one item
/crafting/               stations, converters; /crafting/<slug>/
/building/               pieces by tool and category; /building/<slug>/
/creatures/              bestiary; /creatures/<slug>/ ; /bosses/
/biomes/<slug>/
/locations/              by biome; /locations/<slug>/ one kind (variants grouped)
/effects/<slug>/  /skills/  /traders/<slug>/  /events/
/world/                  the seed viewer (full map)
/search/                 client-side search over search.json
```

Slugs are kebab-case of the English name, de-duplicated with the prefab
when two things share a name. Every reference to a thing is an icon+name
chip linking to its page; "obtained from / used in / found in / dropped
by" tables are reverse indexes computed by the generator.

## Your world (the seed)

A seed is a global lens: `?seed=` in the URL or the last seed in
`localStorage`. Without one every page is complete. With one, pages gain
a "Your world" panel: where the nearest X is, how many were placed,
bearing and distance from the start, a link that opens `/world/` centred
there. The seed engine is `world.wasm` in a Web Worker:

```
page → worker: {type:'open', seed, mapSize}
worker → page: {type:'info', seed, seedNumber, radius, worldRadius, water}
               {type:'map', size, heights:Uint16Array, biomes:Uint8Array, mask:Uint8Array /*RGBA*/}
               {type:'sectors', ids:Uint16Array, list:[{id, biome, names:[...], x, z}]}
               {type:'rivers', rivers:[[x0,z0,x1,z1,wmin,wmax]...], streams:[...]}
               {type:'sites', rule, prefab, xyz:Float32Array, index, total}   // streamed per rule as placed, prioritized rules first; world.js unpacks to {x,z,y}
               {type:'done', report:[{rule, prefab, wanted, placed}], took}
page → worker: {type:'point', x, z}  → {type:'point', x, z, biome, height, depth, forest, sector:[names]}
page → worker: {type:'tile', cx, cz, span, n}  → {type:'tile', n, cx, cz, span, heights:Float32Array /*metres*/, biomes:Uint8Array, mask:Uint8Array /*RGBA*/}   // a close-up grid, row zero north, for the 3D view
page → worker: {type:'zone', zx, zz}  → {type:'zone', names:[prefab...], kinds:[...], ids:Uint16Array, data:Float32Array /*x,y,z,qx,qy,qz,qw,scale per place*/}   // what stands in a 64 m zone: the sites' models and the vegetation
```

The first zone of a cached world costs the engine its biome map once
(progress phase `scene`); the worker hands it the record's sites
(`adoptSites`). `internal/scene` is valheim-world's zone build, ported:
the vegetation rules and placement loop draw for draw, the placement ray
against the prefabs' colliders and the sites' solids, the sites' clear
areas and terrain modifiers (which also reshape the close-up tiles).

`web/static/js/world.js` wraps this: `World.open(seed)` returns a handle
with `onMap`, `onSites`, `onDone` callbacks and `sites()`, `near(x,z,n)`,
`countOf(prefab)`, `start()`; results are cached in IndexedDB by seed and
engine version so a seed is computed once per browser.
`web/static/js/worldmap.js` paints the map (WebGL2, the game's own map
shader with the textures under `web/static/map/`, a procedural fallback
without them) and draws round site icons over it.
`web/static/js/world3d.js` is the same world in three dimensions, loaded
when the World page's 3D switch is first used: the height raster as an
instanced-patch terrain (no vertex buffers; heights read from an R32F
texture by `gl_VertexID`), two nested close-up tiles the engine samples
around the camera's target (`tile`, 2400 m and 600 m at 320 samples a
side), each fading to its parent along its edge while the parent sinks
under it, a depth-tinted sea plane, a sky, and the map's marker overlay
projected onto the ground. `?view=3d&x=&z=&zoom=&yaw=&pitch=` deep-links
a camera; the "Your world" panels link there. Under a kilometre and a
half it draws what stands in the zones around the target: `models.js`
reads the pack under `web/static/models/` — the vegetation meshes as
extracted (VMSH), the sites packed as VMSQ by `cmd/wiki-models` (quantised,
deduplicated, clustered under a 1.8 MB cap; the largest ruins are left
out), their materials and shrunk textures — and the view draws them
instanced with alpha-to-coverage cutouts, foliage thinned about the
camera.

## Style

Go only for tooling; no node toolchain. html/template, hand-written CSS
and vanilla JS modules. Commit messages without AI attribution.
